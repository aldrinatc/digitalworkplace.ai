# Digital Workplace recovery — 16 September 2026

## Causes and deployed repairs

The launcher and Google sign-in loaded, but the apps failed independently. Anthropic credit was depleted (Chat Core's key was also invalid), the direct OpenAI embedding account was unfunded, and routes still named retired Claude models. Several fallbacks presented fabricated demo answers as successful AI responses. Generation now uses the approved Vercel AI Gateway → OpenAI gpt-4o-mini route, restricted to OpenAI, with fresh request-scoped OIDC identity, deadlines, bounded direct-provider fallback and no SDK retry amplification.

Intranet now ranks genuine keyword matches during the embedding outage, including streamed replies, and never sends demo thread IDs to UUID database columns. Test Pilot uses its deployed API prefix, validates personas and labels bundled dashboard context as sample data. Chat Core's ranking no longer lets generic FAQ words hijack specific questions. A verified City Clerk-hours FAQ directly returns its [official citation](https://www.cityofdoral.com/Government-Center/Office-of-the-City-Clerk/Council-Meetings); this does not certify all old demo content as current.

Chat Core conversation logs and feedback now await Supabase persistence. Booking configurations, service requests, channel sessions and workflow state use transactional Postgres storage instead of local files or process memory. Slot reservations serialize competing requests and enforce capacity. Transfer codes are random, expire and redeem once. Booking confirmations correctly say the record was saved and do not claim an email was sent.

Document uploads now store their original bytes, extracted text and searchable chunks in Supabase. The upload URL includes `/dcq`; PDF, DOCX and TXT files up to 4 MB are supported. Replacement and removal archive old versions rather than destroying originals. Document retrieval is connected to chatbot knowledge search. The runtime connection has only the permissions needed by this app.

Support's database URL was an IPv6-only host with a missing database name. It now uses the existing Supabase IPv4 transaction pooler. Missing draft/version/analytics tables were added without altering the shared user tables. Draft API writes, edits, status filters and approvals now persist. Empty queues and database errors no longer become mock records. Existing workplace Clerk sign-in protects the draft APIs and dashboard; the legacy demo-login identity cannot authorize these records. The app's database role is limited to its draft tables and permission metadata. Anonymous database roles cannot read the new tables.

The existing ATC owner's Supabase account had its `super_admin` role but no Clerk ID. The verified `aldrin@atc.xyz` Clerk identity was linked to that existing account in the signed-in Supabase SQL editor; the role was unchanged. Chat Core's permission query also needed an explicit cast for the production `user_role` enum. The sub-apps now refresh the same workplace session using Clerk. No new authentication app was created.

## Funding and monitoring

Vercel auto-reload is enabled with the approved $5 trigger, $25 target and $50 monthly auto-reload cap. The first refill completed. This limits gateway auto-reloads, not unrelated hosting charges or direct-provider spending. Reaching the cap or a failed payment can still stop service.

Four no-generation AI readiness endpoints report gateway/funding health and return 503 below the configured low-credit threshold (default $2). Two database health checks verify actual connectivity/schema access. The work-fork GitHub workflow checks health hourly and runs provider/database regressions on changes. Workflow failure notifications use existing GitHub preferences. The cap and monitoring reduce recurrence risk; they are not a guarantee of uninterrupted service.

3. **Auctor/GRC source access is unavailable to the work GitHub account.** Its public dashboard loaded; no source repair or full workflow certification is claimed for that separate application. A bounded local source search found no Auctor app checkout in Documents.
4. Existing demo datasets and simulated external CRM, telephony, calendar and other connectors remain demonstrations. Existing Supabase advisor and dependency-audit findings outside the repaired paths still require a separate, compatibility-tested security cleanup; no blanket permission changes were applied.
