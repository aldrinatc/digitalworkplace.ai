# Digital Workplace recovery — 16 September 2026

## Confirmed causes

The main launcher, Google sign-in and five product entry pages loaded. AI calls failed separately: Anthropic accounts had exhausted credit (Chat Core's key was invalid), OpenAI embeddings returned credit_balance_exhausted, and several routes requested retired Claude models. Intranet silently returned a VPN demo response to an unrelated remote-work query and attempted UUID queries with `thread-1`. Test Pilot's widget omitted its `/dtq` deployment base path and replaced failures with fabricated metrics. Chat Core persisted conversations and feedback under Vercel's read-only application filesystem.

## Repair

Generation uses Vercel AI Gateway with the official request-scoped OIDC helper (runtime identity is delivered in request context, not a persistent environment variable) and the expressly approved OpenAI/gpt-4o-mini route, restricted to the OpenAI provider. Existing direct provider credentials are bounded fallbacks. Provider calls have deadlines and SDK retry amplification is disabled. No new provider account, key purchase, credit recharge or spend commitment was made.

Embeddings remain on their original OpenAI model/account. Their account still needs funding. Intranet uses ranked keyword retrieval during that outage. Test Pilot uses the same bundled dashboard dataset and explicitly labels it sample data. AI failures no longer masquerade as successful demo answers. Streamed Intranet responses use the same keyword fallback. Test Pilot uses the correct deployed API path.

Chat Core stores conversation logs and feedback in the already-configured Supabase public views and awaits writes before returning. Analytics reads that store. Live answer checks also exposed unrelated curated FAQs outranking city-hours queries; whole-word ranking and explicit evidence-only response rules now prevent that false match. Widget-generated identifiers are preserved as metadata rather than passed to UUID foreign keys. Only synthetic records were used for persistence verification.

Each repaired app exposes a no-generation `/api/health/ai` readiness endpoint beneath its base path. It checks gateway authentication and remaining credit; low credit (default threshold $2) or exhaustion returns HTTP 503. This endpoint does not claim that every integration is healthy and does not expose credentials or balances. `scripts/check-ai-health.mjs` verifies all four apps. The GitHub workflow checks regression tests and polls readiness hourly once installed/enabled on the upstream default branch; workflow failure notifications follow the repository's existing settings.

## Validation and deployment

Local provider integration tests passed for Intranet, Chat Core, Test Pilot and Support. Synthetic conversation and feedback writes passed. Production builds passed for all four apps. Native Node regression tests cover approved routing, credential separation, fallback, exhausted providers, model migration, credit readiness and retrieval behavior. ## Remaining operational dependencies

- Existing gateway credit is finite. An account owner must configure funded billing/auto-recharge and a suitable spending limit in Vercel; no software fallback can guarantee generation when every billing source is depleted. The direct OpenAI embedding account remains unfunded.
- The work GitHub account has read-only access to the original `aldrinstellus/digitalworkplace.ai` repository. Changes must be merged through a work-account fork PR or the work account granted repository write access. Existing project/repository handles are preserved.
- Auctor/GRC's public dashboard loaded, but its private source repository was not accessible to the work GitHub account. No source repair to that separate application is claimed.
- Chat Core also contains legacy file-backed appointment, service-request and configuration workflows, and transient in-memory workflow sessions. Those require a separate durable schema/session migration before they can be represented as a production booking system. They have not been tested by creating real bookings or sending external messages.
- Current product demo datasets and simulated integrations remain demonstrations; restoring AI is not a certification of every external CRM, email, calendar, payment or telephony integration.
